# GameHud: the gamemode HUD kit

`GameHud` from `@s2script/cs2` gives a gamemode a full HUD without writing Panorama: an in-round
layer (top rail, kill feed, status card, weapon card, target label, toast, round-end summary) and a set of panels (pop-up
vote, drawer, sheet, prompt, intro, spectate hub). Names are generic: a drawer can be a TTT shop,
a prompt can be an RDM report, a sheet can be JB rules. The worked example is the cookbook recipe
[`examples/cookbook/src/recipes/gamehud.ts`](../examples/cookbook/src/recipes/gamehud.ts).

## Requirements

- The game-kit workshop addon (`3790153369`) mounted on the server, with the layouts from
  `examples/hud-lab/workshop/` (generated by `scripts/gen-gamehud-layout.mjs`). Republish it after
  any layout change: the server drives fixed panel ids and a missing id fails that one paint.
- Every paint takes an audience: `"all"`, a slot, a player, a list, or a filter `(slot) => boolean`.
  Both layouts spawn with `observable: false`, so a spectator never sees the watched player's panels.

## Surfaces

| Call | What | Cursor | Claim |
| --- | --- | --- | --- |
| `rail()` | top rail: a solid bar over the stock team counter, with two score blocks, pips, clock and sub line | no | one plugin |
| `status()` | role line, hint, two 10%-step bars | no | one plugin |
| `feed()` | kill feed, six rows per player, fades after 6 s | no | one plugin |
| `weapon.claim()` | weapon card: name, clip / reserve, slot list (bottom right) | no | one plugin |
| `target()` | crosshair target label: a name and a small sub line under the crosshair | no | one plugin |
| `toast(audience, spec)` | one line and a sub line | no | shared, newest wins |
| `summary(audience, spec)` | round-end title, stats and a short table | no | shared, newest wins |
| `theme(audience, name)` | accent colour for every piece | n/a | shared |
| `vote(spec)` | pop-up vote, 2 to 8 options | no; type the number or press Tab | one vote server-wide |
| `drawer(player, spec)` | side drawer, 5 tabs, 8 rows | yes, with Close | per player |
| `sheet(player, spec)` | side tabs and a paged body (list, text, toggles, grid, table) | yes, with Close | per player |
| `prompt(player, spec)` | one question, up to 4 answers, optional timer | yes, with Close | per player |
| `intro(player, spec)` | brand, menu, profile card | yes, with Close | per player, shared with spectate |
| `spectate(player, spec)` | menu, player picker, camera shot list | yes, or Tab with `cursor: false` | per player, shared with intro |

**Input rule.** Everything is clickable. The only surface that does not take the cursor is the
pop-up vote, because a player did not open it and may be mid-fight: voters type `1` to `8` in chat
(the line is not shown) or press Tab to click.

**Colour.** Text takes the chat colour tags (`{red}`, `{green}`, `{lightblue}`...), so a phrase
colours the same in chat and on the HUD. A label holds one colour: a leading tag picks it, and the
tags are then stripped.

**Chat fallback.** When the HUD refuses a paint for a live player (the layout entity is missing,
for example), the kill-feed row, toast, summary, vote, drawer, sheet, prompt and hub go to that
player in chat instead. A refused prompt or vote then accepts a typed number.

**Claims.** A claimed surface is held host-side and freed when the plugin unloads, even if the
plugin's own cleanup never runs. A second plugin asking for a held surface gets `null`. A plugin
that is reloaded mid-map gets its surfaces back from `OnPluginStart`: the world is already live, so
claims and paints made there land at once, and a new claim clears what the previous generation left
on screen.

## Top rail

No `m_iHideHUD` bit hides CS2's stock team counter and round timer at the top of the screen, so
the rail covers them. By default it is a solid bar across the full width of the top edge, 116 px
tall at 1080p, in the kit's panel colour, with the score blocks, clock and sub line inside it. The
stock counter is centred, starts about 6 px down and is about 106 px tall in a round. It grows
about 56 px per player on each side, so only the full width is sure to hide it on a big server.

```ts
const rail = GameHud.rail();
rail?.set("all", {
  left: { label: "{red}Prisoners", score: 3, alive: 3, total: 8 },
  right: { label: "{blue}Guards", score: 2, alive: 2, total: 2 },
  clock: "1:42",
  sub: "Round 4",
});
rail?.set(slot, { cover: false }); // the floating look for this player: blocks only, stock counter shows
```

The bar overlaps the top 70 px of the stock radar and the first row of the stock kill feed. A mode
that keeps the stock radar and does not want that passes `cover: false`, which is the floating look
(score blocks and clock only). `cover` is per player and sticky like every other field, and a new
owner of the rail starts everyone on the cover again. While a player is dead or spectating, the
stock counter adds an equipment row and reaches about 182 px; the part below the bar shows then.
Like the rest of the rail, the bar collapses under the scoreboard and the buy menu.

## Weapon card

`Hud.hide(slot, HideHud.Weapons)` (m_iHideHUD bit 6) hides the stock weapons HUD: ammo, weapon name
and slot list. The weapon card puts them back, bottom right, in the status card's style:

```ts
import { Hud } from "@s2script/sdk";
import { GameHud, HideHud } from "@s2script/cs2";

if (GameHud.weapon.claim()) {
  Hud.hide(slot, HideHud.Weapons);
  GameHud.weapon.auto("all", { name: (defIndex) => shopNames[defIndex] ?? null });
}
```

- **`auto(audience, options?)`** fills the card from each player's pawn. Each player is read once every
  4 frames (about 16 Hz), with the players spread across those frames: the active weapon's clip and
  reserve on every read, the held weapons and the slot list every 4th read and on every switch. Only
  what changed is sent. The clip turns red at or under 25% of the magazine. Knives and C4 show only
  the name; grenades show a count. The card hides while the player is dead or spectating, and
  follows a bot the player has taken over. `options.name(defIndex, weapon)` renames items (return
  `null` to keep the default); `options.hideSlots` drops the slot list.
- **Slot rows** show each item as the game's own equipment icon (the name instead when an item has
  no icon, and both for a renamed item). The knife and the Zeus share a row, and so do the
  grenades: the item in hand is at full strength and the others are dimmed, decided by the weapon
  entity so two items with one name still differ. Items sit knife before Zeus and grenades in buy
  order, and a row past four ends in "+N". `options.icon(defIndex, weapon)` swaps in your own image.
- In `set`, a row is a string, or `{ items: ["Knife", "Zeus"], active: 0 }` to mark one item. An
  item can also be `{ text, icon }`.
- **`set(audience, { name, icon?, clip?, reserve?, count?, tone?, slots? })`** paints it yourself, and
  **`hide(audience)`** hides it. Both take that audience out of `auto` until `auto` names them again.
- `claim()` answers `true` when this plugin holds the card. Every other call throws until it does.
  `release()`, or unloading the plugin, hides the card and stops `auto`.

## Target label

A small label centred just under the crosshair for "who you are looking at": one name line and an
optional sub line (a role tag, health, "Detective"). It never takes the cursor and collapses under
the scoreboard and buy menu.

```ts
import { GameHud, Player } from "@s2script/cs2";

const target = GameHud.target(); // null when another plugin holds it

export function OnGameFrame(): void {
  for (const p of Player.all()) {
    const seen = whoIsAimedAt(p);   // your aim trace (pawn.aimTrace) and rules
    if (seen) target?.set(p.slot, { name: "{red}" + seen.playerName, sub: "Traitor" });
    else target?.hide(p.slot);
  }
}
```

- **`set(audience, { name, sub?, tone? })`** shows it. Call it as often as you like: a player whose
  label already says this gets nothing sent. `tone` (or the name's leading colour tag) colours the
  name; the sub line takes its own leading tag, else grey. Leaving `sub` out drops the line. A new
  name while the label is up swaps the text at once.
- **`hide(audience)`** fades it out. Both directions take about 0.1 s, and the label collapses only
  after the fade has finished and nothing showed it again, so an aim sweeping across a gap between
  two players dips and comes back instead of blinking.
- `release()`, or unloading the plugin, hides it for everyone and frees it for another plugin.

## Rules with stable numbers

A sheet section's list items are numbered by their place in the whole section (or by their own
`n`), not by their place on the page. So a plugin can hand over all 14 rules, let the sheet show 6
at a time, and still open it on rule 9, highlighted:

```ts
GameHud.sheet(slot, { title: "Rules", sections, section: "rebels", highlight: 3 });
```

The cookbook reads its rules from `configs/gamehud-rules.json` (written on first use), so an
operator edits rules without a rebuild, and `sm_rules @player rebels 3` opens that rule for a player.

## Camera shots

The spectate hub moves the player's own observer camera with the commands a spectator would type,
run through `Client.fakeCommand`: a follow shot is `spec_mode 2|3` and `spec_player <slot+1>`, a
fixed shot is `spec_mode 4` and `spec_goto x y z pitch yaw`. They only act while the player is
observing (dead or on the spectator team).

## Live check

Run these on the Docker dev server (`make docker-test`) with the cookbook loaded and the addon
mounted, from a real client (bots have no HUD). Each line is pass or fail; note the build.

1. **In-round.** `sm_gk_on teal`. The rail shows both teams with pips, and the status card shows your
   role and two bars. Add bots (`bot_add`), kill one: a feed row appears with the weapon icon and
   fades after about 6 s. Open the buy menu and the scoreboard: the rail, feed, status and toast
   collapse and do not block clicks (the summary collapses under the buy menu only).
2. **Audience.** With a second client spectating you, the spectator does not see your status card.
3. **Toast and summary.** `sm_gk_toast {orange}Hi` shows a toast with an orange edge. End a round
   (`mp_restartgame 1` or kill everyone): the summary shows the winner in the team colour, stats and
   a table, and hides on the next round start.
4. **Vote.** `sm_gk_vote`. The vote appears and the mouse still aims. Type `2` in chat: the line
   does not show, your choice is marked and counts appear. Press Tab, click option 1: it moves. After
   20 s a toast reports the result.
5. **Drawer.** `sm_gk_shop`. The cursor appears; switch tabs, click a row you can afford, and the
   credits go down. Close releases the cursor.
6. **Sheet.** `sm_rules general 9` opens page 2 of 3 with rule 9 highlighted. Page with the arrows
   and the dots. Click the Teams header: it opens Guards. `sm_rules @me rebels 3` opens Rebels on
   rule 3. Edit `configs/gamehud-rules.json`, run `sm_rules` again, and the change shows.
7. **Prompt.** `sm_gk_ask`. The timer counts down from 15 s; click an answer and the server log shows
   it. Run it again and press Close: the log says `closed`.
8. **Intro and spectate.** `sm_gk_intro` shows the brand, menu and card. Click Spectate: you move to
   spectators and the hub shows a picker and the Overview shot. Click a player: the camera follows
   them in first person and the card is marked. Wait 8 s: the shot list advances. **Check whether
   `spec_goto` moves the camera without `sv_cheats`**; if it does not, fixed shots need another
   route. Click Back: the intro returns. Click Join a team: you join the smaller side.
9. **Fallback.** Unmount the addon (or remove `s2script_gamepanels.xml`) and run `sm_gk_vote`,
   `sm_rules` and `sm_gk_ask`: each arrives in chat, and typing a number answers the vote and prompt.
10. **Weapon card.** `sm_gk_weapon`. The stock ammo and weapon list disappear and the card shows
    your weapon and `clip / reserve`. Fire: the clip counts down with each shot and turns red at a
    quarter of the magazine. Reload, switch to the pistol, knife and a grenade (the knife shows only
    its name, a grenade shows `×N`), buy and pick up a weapon: the slot list follows and the active
    row is marked. Every stock item shows its icon (note any that is blank). With a knife and a Zeus,
    the knife is bright and the Zeus dim, and switching flips them at once; the same for the grenade
    in hand. A Desert Eagle reads "Hand Cannon". Die: the card disappears while you spectate
    and comes back on respawn. `sm_gk_weapon off`: the stock HUD returns.
11. **Unload.** `sm plugins unload @example/cookbook` while a vote, sheet, rail and weapon card are up: everything hides
    and a second plugin can claim the rail.
12. **Reload.** With the rail, status card and weapon card up, `sm plugins reload @example/cookbook`: all three
    come straight back with fresh content (no `world not ready` line in the log), and nothing the old
    generation painted is left behind.
13. **Target label.** `sm_gk_target` with a few bots (`bot_add`, `bot_stop 1`). Aim at a bot: its name
    shows under the crosshair in its team colour with its health under it, and fades in rather than
    popping. Look away: it fades out. Sweep across two bots standing apart: the label follows from
    one name to the next without blinking, and dips only over the gap. Note how far below the
    crosshair it sits (aim for about 60 px at 1080p). Open the scoreboard and buy menu: it
    collapses. `sm_gk_target off`: it hides.
14. **Rail cover (screenshots).** `sm_gk_on teal` with bots filling both teams (`bot_quota 10`).
    Take one screenshot in a round at 16:9 (1920×1080) and one at 4:3 (1440×1080, or 1280×960),
    each with the default HUD scale and once with `safezoney 0.85`. Pass: no part of the stock team
    counter, avatars or timer shows around or through the bar, and the rail's scores, pips, clock
    and sub line read clearly inside it. Note how much of the radar the bar hides. Then die and
    screenshot while spectating: note whether the stock equipment row shows under the bar. Open the
    scoreboard and the buy menu: the bar collapses. `sm_gk_rail float` (or `cover: false` from a
    plugin): the floating blocks return and the stock counter shows around them. Save the shots
    next to the build number in the PR or live-gate log.

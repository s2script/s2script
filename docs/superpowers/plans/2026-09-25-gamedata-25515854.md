# Gamedata refresh for CS2 build 25515854 (2026-09-25)

CS2 build 25515854 (patch 1.41.8.4, Sep 24) broke 16 shipped signatures: 8 in core gamedata and
8 CS2 package calls, one of which also feeds the `onTerminateRound` hook. One more, `EndTouch`,
was already degraded on the previous build. Every other signature still resolved uniquely.

## Inputs

| | Build | `libserver.so` SHA-256 |
|---|---|---|
| Previous (every broken signature resolved uniquely here) | 25218825 | `a4c54f83bb48…` |
| Current (Steam public build when checked) | 25515854 | `dffed53d94ab…` |

source2rosetta's newest release was 25218825, one build behind. Its signatures matched only
`FireOutputInternal` and `TerminateRound` on 25515854, and both of those hit **different
functions** from ours (checked on both builds), so no rosetta signature was used. Every result
below was derived from our own previous-build body and verified on the new binary.

## Method

1. Resolve each old signature on 25218825 to get the old function.
2. Find its 25515854 counterpart by one or more of:
   - **Sequence match**: normalized instructions (registers and opcodes kept, immediates and
     displacements masked), scored over 100 instructions against every new position that shares
     the opening instructions.
   - **RTTI vtable slot**: the old slot index in the class's primary vtable, shifted by the
     virtuals inserted this update, then confirmed by body.
   - **String anchor**: a unique string the function references (a log format or a
     profiling-scope label).
   - **cs_script wrapper**: the wrapper's argument-description string, e.g.
     `(mode: CustomCameraMode)`, is at the same distance from the method call on both builds.
3. Cut an instruction-aligned pattern that masks call/jump targets, RIP displacements, struct
   field displacements and stack-frame sizes, extended until it matches exactly once.

## Ties broken by validators (shim change)

`StartTouch` and `EndTouch` are thin shapes that other classes share byte-for-byte (2 and 8
matches). A direct recipe now runs its own validators over every match and accepts only when
exactly one passes. The `lea-disp` and `ctor-body-xref` strategies keep the strict single-match
rule. `vtable-member CBaseTrigger` keeps `0xd691d0` and `0xd36810`. Covered by
`validators_break_direct_ties` in `shim/tests/engine_resolver_test.cpp`.

`EndTouch` was already broken before this update: its pattern matched the implementation
behind the thunk (`0xd3ea70`), which is not a vtable slot, so the type had been degraded with
"NOT a member of … CBaseTrigger" on 25218825.

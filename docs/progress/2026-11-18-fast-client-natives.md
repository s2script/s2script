**Fast client and slot natives (2026-11-18). Unit-tested, not live-tested.** `Clients.all()`, `Clients.fromSlot`, `Player.all()` and `Player.allConnected()` checked each slot through hand-written natives that build and parse a decimal token string per call: 64 slots cost 8.7 µs. Four new `native!` fast natives in `core/src/client.rs` (`__s2_client_live`, `__s2_client_generation_n`, `__s2_client_matches_n`, `__s2_client_connected`) and `__s2_ent_id_for_index` (now `native!`, fast) bring the same scan to 0.6 µs. `Client` keeps its connection token as a number (connection ids count up from 1, exact in a double); the token-taking natives that still parse a string accept it through ToString, so no other native changed. `EntityRef.readHandle` reads through the fast `__s2_ent_ref_readf` first, and `Player.fromSlot` looks up the `m_hPlayerPawn` offset once. Live check: `sm plugins`, targeting (`sm_slay @all`), and anything that lists players behave as before.

**Movement hook view cost (2026-11-21). Unit-tested, not live-tested.** A live `sm prof` on a TTT server put one plugin's `movement.onProcessMove` handler at 0.12 ms a call, 36,481 calls in 60 s: the largest line in the report, for a handler that did nothing but read `view.player`. Two costs were in `games/cs2/js/adapters/process-move.js`, paid by every subscriber on every player's movement tick. The view was built with seven closures and an `Object.defineProperties` call each time, about 2 us in Node before the handler ran. And `view.player` scanned the player slots from 0, building a pawn for each slot until one matched. The view is now a class with private fields and prototype accessors, so a handler that reads nothing costs one small object (2041 ns to 21 ns in Node fakes). The player scan starts at the slot that matched last and wraps, so the same player's next command matches on the first probe and the next player's on the second, and the answer is kept for the life of the view (2192 ns to 107 ns with 12 players, where the fake pawn is a plain object; the real one is far dearer). Contract and API unchanged. Live check: `sm prof start 60` shows a movement-hook plugin's `Engine.function hook` average well under 0.12 ms, and `view.player` still names the right player with several players moving.

**PROGRESS.md entries become per-PR fragments (2026-11-09) — tooling; no runtime change.** Prompted by three open PRs conflicting on `docs/PROGRESS.md` on Nov 8: every slice prepended its entry to the same lines at the top of the log, so the second PR to merge always conflicted. A PR now adds its entry as `docs/progress/YYYY-MM-DD-<slug>.md` and never edits PROGRESS.md, like a changeset. `scripts/progress.mjs check` (in `ci-js`) validates fragment names and bodies; `scripts/progress.mjs fold` prepends them newest-first under `## Current state (full history)` and deletes them, and runs inside `npm run version-packages`, so the changesets "version packages" PR carries the fold. `merge=union` in `.gitattributes` was rejected because GitHub's web merge ignores custom merge drivers. CLAUDE.md, PROGRESS.md's header and `docs/progress/README.md` describe the new flow.

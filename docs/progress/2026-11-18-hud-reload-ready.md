**HUD surfaces come back after a plugin reload (2026-11-18). Unit-tested, not live-tested.** A plugin reloaded mid-map could not get its HUD back from `OnPluginStart`. The host claim table was not the cause: unload frees a plugin's `__s2_ui_pool_claim` claims through the ledger, and the new generation reclaims them (a new in-isolate test, `native_reload_reclaims_a_single_owner_region`, pins that). The cause was in `ui.js`: each plugin's ui base decided it was "ready" only from inside its `reg` registrations, and the load window buffers those until `OnPluginStart` has returned. So every paint, region claim clear and modal open made from `OnPluginStart` failed with "world not ready" and was dropped, even with players on the server and the layout entity still alive, and the previous generation's last paint stayed on screen. First boot hid this, because no client is active then and plugins paint on later events. The ui base now also checks for an active client when it is built (a read that registers nothing), so a plugin loading into a live world adopts the surviving layout entity and paints at once; arming afterwards does not spawn a second entity. `docs/GAMEHUD.md` gains a reload step in the live check.

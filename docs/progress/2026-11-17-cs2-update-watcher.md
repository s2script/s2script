**CS2 update-day watcher (2026-11-17). Checked offline against the Nov 5 → Nov 11 builds; the workflow has not run yet.** Update day used to be done by hand. Now `.github/workflows/cs2-update.yml` reads Steam's public manifest for depot 2347773 every 5 minutes, and `repository_dispatch` `cs2-update-poll` lets a faster external poller wake it. When the manifest differs from `tools/gamedata-offline/baseline.json`, the workflow downloads the new modules with `fetch-depot.sh` (DepotDownloader 3.4.0, sha-pinned, anonymous login). It gets the baseline build's modules from its own Actions cache, or downloads the baseline manifest when the cache has expired. Then it runs `update-day.sh` and files one `cs2-update` issue per build. `update-day.sh` runs check.py with the new `--all-vtables` slot-count diff of every RTTI vtable (the check that found the Nov 11 INetworkMessages break by hand), runs schema.py, and runs the new `schema_diff.py`, which reports moved, added and removed fields. check.py also gained `--markdown` and `--strict`. A vanished fingerprint in a table that kept its size now counts as a recompiled body and is no longer flagged. After filing the issue, the job runs `anthropics/claude-code-action` on the same files. Claude fixes what the report flags, regenerates the schema, bumps the baseline and opens a draft PR through the Claude app, so CI runs on it. This step needs a `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` secret and is skipped without one. Steam binaries stay in the Actions cache. The artifact holds only the report and the regenerated catalog.

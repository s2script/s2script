**basecomm `sm_mute` no longer triggers CS2's report-abuse mute (2026-11-10) — offline; live acceptance pending.** Prompted by a live server where `sm_mute` made every client print "<name> has been muted for receiving significantly more communications abuse reports than most players". basecomm already enforced the mute through `Client.voiceMuted` (the shim's `SetClientListening` rewrite, so the sender is inaudible to every receiver), but it also wrote the controller's `m_bHasCommunicationAbuseMute` as a "cosmetic scoreboard indicator". That flag is the matchmaking report-abuse mute, and the client announces it. basecomm now writes only `voiceMuted`, on mute, unmute and the reconnect re-assert, which matches SourceMod's `SetClientListenFlags(VOICE_MUTED)` behaviour: the player just can't be heard. The plugin tests assert the flag is never set. A player muted under the old build keeps the flag until they reconnect.

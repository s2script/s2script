**Config hot reload for every plugin with config (2026-11-17). Unit-tested, not live-tested.** The loader only watched a plugin's `configs/<id>.json` once the plugin called `config.onChange`, so a plugin that reads `config.getInt(..)` when it needs a value (the s2s-jb rtd/specialdays/core pattern, and what `config.d.ts` shows) never saw an edit until it was reloaded. `begin_load_prepared` now starts the watch for every plugin that declares `s2script.config`; an edit re-materializes `__s2pkg_config_values` (so the getters read the new value) and fires any `onChange` handlers. New test `a_config_edit_reaches_getters_and_on_change` covers a getter-only plugin and an `onChange` plugin, including after a map change on a hibernating server. The watch is still frame-driven: an empty server with `sv_hibernate_when_empty 1` picks up the edit when frames resume (a player joins) or at the next map start. Live check: edit an s2s-jb rtd value (`rtd_minplayers`) with a player on, wait ~1 s, and confirm the new value applies without `sm plugins reload`.

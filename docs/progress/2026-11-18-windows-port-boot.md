**Windows port W1: core and shim build for Windows x64 (2026-11-18). Build-tested in CI, not live-tested.** The first step towards a second Source 2 game, since Deadlock's dedicated server ships only Windows binaries. It is proven on CS2 first, where every engine fact can be checked against the Linux build. `scripts/build-windows.sh` cross-builds from Linux with clang-cl, lld-link and the MSVC CRT from xwin: core becomes `s2script_core.dll` and the shim becomes `s2script.dll`. The script checks that neither DLL needs a redistributable, that the shim delay-loads core and that it exports `CreateInterface`. It then packages `bin/win64/` and a Metamod VDF. A new `windows` ci-native shard runs it. The shim's OS calls go through one seam, `shim/src/platform.h`, with POSIX and Windows halves; the Linux behaviour is unchanged. Core is delay-loaded and preloaded by full path, because Windows does not search a plugin's own directory for its dependencies. The gamedata key on Windows is `win64`; no gamedata has one yet, so every descriptor degrades with its named reason. Subsystems that need a real port refuse with a named reason: vtable lookup by name (MSVC RTTI), engine calls (Microsoft x64), the engine-function bridge, detours, plugin function overrides, crash capture and native extensions. Spec: `docs/superpowers/specs/2026-11-18-windows-port-design.md`; the live gate is in `docs/superpowers/plans/2026-11-18-windows-port-boot.md`.

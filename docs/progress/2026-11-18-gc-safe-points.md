**Garbage collection at safe points (2026-11-18) — offline; live check pending.** V8 collected only when an allocation forced it, in the middle of whichever handler allocated; with twenty plugins a full collection pauses for 5 to 8 ms in the core harness, enough to make an ordinary frame a slow one. The host also never ran V8's foreground task queue, where V8 posts incremental-marking steps and FinalizationRegistry cleanup, so that work waited for a forced collection and finalizer callbacks never fired at all. `core/src/gc_points.rs` now arms a full collection at map start and runs it on the first frame POST after the loader has settled (or after 600 frames), logging `[s2script] garbage collected after map start: <ms>, heap <before> MB -> <after> MB`; and the end of every frame POST runs at most one posted V8 task. One, not the whole queue: running it all at once did every marking step in one frame in the harness (10 to 27 ms frames). In the harness one task a frame lowered the median full pause from 5.0 to 3.4 ms at 20 plugins; the longest pauses did not move, so the live `[s2script] slow frame:` lines decide whether it stays. Live check: after a map change the log shows the collection line once; `sm frames` totals show fewer full collections per hour than before.

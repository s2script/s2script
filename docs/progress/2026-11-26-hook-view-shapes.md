**Hook callback views from shapes built once (2026-11-26). Unit-tested, not live-tested.** A live `sm frames` on a TTT server counted a full collection every 1.2 s, and `sm prof` put the framework's `dispatch_function` at 0.042 ms a call over 93,468 calls. Both came from `core/src/v8host/function_adapter.rs`: every hooked engine-function call built its frame view from fresh `v8::Function`s, a getter and a setter per parameter, plus the adapter's cursor. V8 allocates a function template for each such function in the old generation, so the garbage could only be reclaimed by a full collection. In the core harness one hooked call (PRE and POST, one adapter, one subscriber) cost 23.8 us, and 200,000 calls ran 118 full collections. Views are now instances of a `FunctionTemplate` built once per shape (`function_adapter/leased.rs`): the accessors are shared, the lease is the instance's internal field, and a signature makes V8 refuse an accessor run against anything that is not an instance of the same shape. The lease is validated on every access exactly as before. Same harness: 9.3 us a call, no full collection, 14 ms of young collection in place of 238 ms of full. A second pass over the same path took it to about 6 us: the adapter's `{frame, phase, cursor}` object is a shape too, the names of host-made properties and the delivery tag's private key are made once, a lease check compares the context's owner in place instead of building a key, an `OwnerKey` shares its id rather than owning a `String` (it is cloned for every lease), and the maps keyed by plugin id (`PLUGINS`, the liveness tables) use a cheap hasher (`core/src/fasthash.rs`), which every dispatch and every owner check in the runtime pays less for. One behaviour is stricter: `overrideReturn`, `hiddenReferencedBy`, `cursor.invokeNext` and the accessors only run with their own view as the receiver, so a method detached from its view (`const f = frame.overrideReturn; f(1)`) now throws. The shipped adapters all call them as methods. Live check: `sm frames` on a server with a movement or weapon hook subscribed shows full collections at a small fraction of one per second, and `sm prof start 60` shows `dispatch_function` well under 0.042 ms.

**Per-tick hooks through the JS multiplexer (2026-11-18). Unit-tested, not live-tested.** Usercmd pre and post, entity lifecycle listeners, the per-entity SDKHooks that take only the entity (Think, Spawn, PostThink, ...) or the entity and another (the touch family), and SetTransmit now cross into JS once per dispatch instead of once per subscriber (`core/src/jsmux.rs`, `core/js/mux.js`), the same machinery game events and `OnGameFrame` already used. A new `Payload::Made` hands each subscriber arguments built by a small function compiled in its own context from the plain values the crossing carries (indices, host ids, a slot, a class name), so a handler never receives an object from another realm; the books are checked once in Rust before the crossing. The multiplexer now passes up to four shared arguments, and its argument list lives on the stack (the usercmd post zero-allocation test holds). The SDKHook store gained a version so the multiplexer knows when a channel's array is stale; per-entity channel names are not cached. Collapse, breadcrumbs, WARN labels and crash reports match the Rust fan-out, which remains the profiler's path. Entity events now dispatch the exact-class channel and then the wildcard as two crossings, so the wildcard's subscriber list is read after the exact handlers ran (a wildcard subscribed by an exact handler now sees the same event). Measured in the core harness: usercmd pre to 10 plugins 10.5 us to 1.1 us per command. SDKHook `Use`, entity output/input, client events, usermsg and engine-function hooks stay on the Rust fan-out. Live check: usercmd, SDKHooks, SetTransmit and entity listeners behave as before; `sm frames` with a busy server shows a lower s2script share.

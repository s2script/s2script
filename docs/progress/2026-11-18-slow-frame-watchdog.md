**Slow-frame watchdog (2026-11-18) — offline; live check pending.** Small "slow server frame" warnings could not be attributed: `sm prof` only sees frames while it records, and while it records dispatch takes the Rust fan-out instead of the JS multiplexer, so it measures a slower path than the one that normally runs. The new `core/src/frame_watch.rs` times every entry from the engine into the core (the outermost one only, so a nested dispatch is not counted twice) and every V8 young and full collection through GC callbacks installed for the isolate's lifetime. A frame runs from one `GameFrame` POST to the next, so calls the engine makes between frames are counted too. When s2script's share of a frame reaches the threshold (4 ms by default) the log gets one line, at most one a second, such as `[s2script] slow frame: s2script used 6.8 ms (of which garbage collection 6.1 ms, 1 full; OnGameFrame post 6.5 ms)`. `sm frames` prints totals (frames, frames over the threshold, longest young and full collection); `sm frames <ms>|off|reset` sets the threshold, stops the line, or zeroes the totals. Three FFI entries carried the next entry's profiler span (Touch had game_event_pre's, usercmd had CanBeAutobalanced's, the engine-function hook had usercmd's, cvar change had the hook's); each entry now opens its own. Live check: on a running server, `sm frames 0.01` prints a line per second naming the parts; `sm frames` shows nonzero young collections after a few minutes; `sm frames off` stops the lines.

**GameHud panels stack above the intro and spectate hub (2026-11-21). Unit-tested, not live-tested.** When a player had the intro (or the spectate hub) open and another plugin opened a sheet for them, the intro covered the sheet and swallowed its clicks. The hub was the last child of `s2script_gamepanels.xml`, and Panorama draws later siblings on top and hit-tests them first, so the full-screen hub sat over every other panel no matter which opened first. `scripts/gen-gamehud-layout.mjs` now emits `gk_hub` as the first child of the panels layout, and `scripts/gamehud/base.css` gives `.gk-hub` `z-index: 0` and the vote, drawer, prompt and sheet `z-index: 10`, so a panel opened over the hub always draws on top and takes the click. Input capture was already a per-panel union on the shared layout entity, so closing the sheet leaves the hub's cursor in place; no runtime change. `gamekit-hub.test.js` checks the layout order and the z-index. The layout and stylesheet changed, so addon 3790153369 needs a recompile and republish. Live check: open the intro, then open a sheet, prompt or drawer for the same player from another plugin; it draws over the intro and its rows and Close respond, and closing it returns to the intro with the cursor still free.

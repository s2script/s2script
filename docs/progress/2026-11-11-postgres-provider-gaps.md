**Postgres provider: SourceMod config names and typed columns (2026-11-11) — offline; tested against a local PostgreSQL 16, live CS2 acceptance pending.** Prompted by a request to add a PostgreSQL provider. One already ships (the July remote-SQL slice), so this slice closes the two gaps a SourceMod author would hit. First, `databases.json` now accepts SourceMod's `databases.cfg` spellings. `"driver": "pgsql"` (and `"postgresql"`) select the built-in Postgres driver, and `"pass"` is read when `"password"` is absent. Before, `pgsql` logged "unknown driver" and quietly fell back to a local SQLite file. Second, columns that Postgres sends only in binary now decode instead of reading back as `null`. Those are NUMERIC/DECIMAL (a decimal string, full precision up to rust_decimal's 28 digits), DATE (`YYYY-MM-DD`), TIME (`HH:MM:SS[.fff]`), TIMESTAMP/DATETIME (`YYYY-MM-DD HH:MM:SS[.fff]`), TIMESTAMPTZ (UTC ISO 8601, `…T…Z`), UUID (hyphenated) and JSON/JSONB (compact JSON text). MySQL gets the same typed fallbacks; every arm still tries the text protocol first, so a value that decoded before decodes identically. The typed decodes go through the same result-size cap as raw text. They come from sqlx's `chrono`/`rust_decimal`/`uuid`/`json` features, enabled on `sqlx-core`/`sqlx-mysql`/`sqlx-postgres` directly, because the umbrella crate's features name `sqlx-sqlite` weakly and that drags its `libsqlite3-sys` into the resolve against rusqlite's `links = "sqlite3"`. The live decode test (`sqldb::tests::postgres_typed_columns_decode_to_text`) runs only when `S2_TEST_PG` holds a connection entry. Not covered: NUMERIC beyond 28 significant digits, NaN or infinity (still `null`), TIMETZ, INTERVAL, BYTEA, and arrays. A string parameter bound into a BIGINT column still needs an explicit `?::bigint` cast on Postgres.

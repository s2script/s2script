**`sm plugins update` finishes on a hibernating server (2026-11-14) — offline; live check pending.** `sm plugins update` often looked like it did nothing. The registry operation itself (plan, download, sha256 check, rename into `plugins/`, lock) runs on its own thread, but its console report and the hot reload of the swapped-in `.s2sp` both run from the `GameFrame` hook's loader poll. An empty server with `sv_hibernate_when_empty 1` runs no frames, so the console printed "working…" and nothing else, and `sm plugins list` kept showing the old version until a player joined. `sm plugins load|unload|reload` had the same gap. The frame hook now records when the last `GameFrame` ran (`loader::note_frame`); a server-console `sm plugins install|update|remove|enable|disable|outdated|load|unload|reload` on a server that has run no frame for 500 ms finishes the work in the command: it waits for the registry operation (bounded at 120 s), prints its report, then `loader::settle_without_frames` pumps the loader at frame pace (the startup load's own step) until a scan started after the command finds nothing left to load (bounded by the startup load's 45 s budget). A ticking server is unchanged: its watcher gets there within a second. Live check: on an empty server, publish a new patch version of an installed plugin, run `sm plugins update`, and the report plus the reload line print before the prompt returns; `sm plugins list` shows the new version.

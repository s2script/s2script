**GameHud layouts pass CS2's CustomHud whitelist, with a CI gate (2026-11-22). Fixes a live failure.** The published game-kit addon failed to load in game: `[custom_hud] Layout contains disallowed attribute textureheight for panel type 'Image'` for `s2script_gamehud.xml`, so the whole in-round HUD (rail, feed, status, weapon card, target label) never appeared. The weapon icons (#405) were sized with `textureheight`/`texturewidth="-1"`, which our CustomHud notes listed as allowed and the live client rejects; every deploy since copied them, and nothing between the generator and the Workshop checks markup, because the resource compiler accepts it. `scripts/gen-gamehud-layout.mjs` now writes every `Image` with only `id`, `class` and `src` (no `scaling`, which #393 stripped only by hand at deploy time, and no texture size) and sizes the weapon icons in CSS instead. CSS stretches an Image's texture to its box, so the box keeps each icon's own shape: a fixed height (16 px in the slot list, 22 px in the header) and a width class `gk-ar-3..28` (width over height in eighths, `height-percentage`), which `gamekit-weapon.js` picks per icon from an `ASPECT` table measured from the viewBox of the game's own equipment SVGs (CS2 build 11259529: 80 of 101 are 32 tall, ratios 0.47 for the smoke grenade to 3.42 for the AWP); an icon not in the table (a gamemode's own) gets a 2:1 box. New gate `scripts/check-custom-hud-layout.mjs` (with `check-custom-hud-layout.test.mjs`), run by `ci-js.sh`, parses every workshop layout under `examples/` against the per-tag list the current client builds, read from client.dll of CS2 build 11259529 (`Panel` id/class/hittest, `Label` +text, `Image` id/class/hittest/src/languages, `Button` id/class), rejects any other tag or node, an id on the outer panel, and a non-stylesheet include; on the old main it reports the 6 + 8 `scaling` and 21 `textureheight`/`texturewidth` attributes. Re-derive the table from the binary when CS2 changes it.

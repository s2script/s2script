**Client names follow in-game renames (2026-11-17) — offline; live check pending.** `Client.name` (and everything built on it: the shim's console-command log line, `Activity.show`/`Activity.log`/`describe()`, chat name substitution, target matching) read the userinfo `name` convar, which keeps the name the client connected with. A plugin that renames players after they join (`player.setName`, or a community/clan-tag renamer) writes the controller's `m_iszPlayerName`, so logs kept showing the original Steam name. The shim's `client_name` op now reads `CBasePlayerController::m_iszPlayerName` (resolved by name through the schema system, the Source 2 base class) and falls back to the userinfo name only while the controller doesn't exist or the field is missing. Live check: rename a player with a plugin, run an admin command as them, and the server log shows the new name.

**`sm plugins info` and versions in `sm plugins list` (2026-11-14) — offline; live check pending.** `sm plugins list` printed only `"id" (running)`, so an operator could not tell which version of a plugin was running, and there was no `sm plugins info`. The SDK build now copies npm's own `description`, `author` (the name, from either npm form) and `homepage` into the `.s2sp` manifest as `description` / `author` / `url`; the loader reads them as optional fields (an older `.s2sp` still loads and lists without them; an older runtime ignores them) and keeps, per plugin id, the manifest fields of the copy it last started, or refused when nothing was running — a refused reload keeps the running version's row. `sm plugins list` now prints `[S2S] Listing N plugins:` then `  NN "id" (version) by author`, a `<Failed>` / `<Unloaded>` / `<Waiting>` / `<Loading>` tag before any plugin that is not running, and an `Errors:` block with each failure's reason. `sm plugins info <#|id|folder/id|file>` prints `Filename`, `Title` (id and description), `Author`, `Version`, `URL`, `Status`, and `Error` for a failed load. A player's own `sm plugins` shows the version and author too. `Plugins.list()` gains `version`. Every base plugin's `package.json` now carries a description, author and homepage. The mixed-live soak counts running plugins from the new list format. Live check: `sm plugins list` shows the stamped version on every base plugin, and `sm plugins info 1` prints the block.

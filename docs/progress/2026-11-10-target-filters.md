**SourceMod multi-target filters for `Player.target` (2026-11-10) — offline; live acceptance pending.** Prompted by admins expecting `sm_slay @ct` / `sm_slap @dead` to work as on SourceMod; `Player.target` only knew `#userid`, names, `@all` and `@me`. The `@s2script/cs2` resolver now also takes `@alive`, `@dead` (spectators count as dead, as in SourceMod; a player in a bot takeover counts as alive, and `@aim` traces from the bot body they are playing; a hit on a taken-over bot's body resolves to the bot, whose `player.pawn` is that body), `@bots`, `@humans`, `@!me`, `@aim` (the player whose body the caller's crosshair trace hits, matched against each player's pawn ref so a non-pawn hit is never misread; a dead or spectating caller gets nothing), and the team filters `@ct`, `@t`, `@spec`. Every base plugin that resolves targets gets them with no change, and the existing `filterImmunity` flag applies to groups as it does to names. The filter table lives in the game package because team numbers are a CS2 fact; it publishes each filter's group label (`__s2_target_labels`) and the engine-generic `Activity.targetName` reads it, so activity lines say "slayed all Counter-Terrorists" like SourceMod's `tn_is_ml` names instead of "N players". The generic labels are phrase keys in `common.phrases.json`; the team labels fall back to English unless an operator's phrase file defines the key. Not covered: plugin-registered filters (SourceMod's `AddMultiTargetFilter`) and `#STEAM_`/`#steamid64` targets.

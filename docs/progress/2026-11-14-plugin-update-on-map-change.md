**Registry plugin updates at every map change (2026-11-14) — offline; live check pending.** The runtime checked the registry for plugin updates only at startup, so a server that stays up across many maps kept the versions it booted with. `plugins.json` gains `updateOnMapChange` (default `true`; `autoUpdate: false` turns it off too). At every map start after the first, the loader first settles anything a background update swapped in while the server ran no frames (`settle_without_frames`), then `server_update::check_on_map_change` runs the same operation as `sm plugins update` on the console-operation thread: the map is not held for the registry, its report prints like a console command's, and the frame watcher hot-reloads what changed. It is skipped (one log line) while another `sm plugins` operation or the startup update still runs. Live check: publish a new patch version of an installed plugin, `changelevel`, and the console shows `[update] map change: checking …`, the install line, and the plugin reloading; `sm plugins list` shows the new version.

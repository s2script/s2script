**Optional provider calls during consumer unload (2026-11-21). Unit-tested, not live-tested.** Reloading TTT Core on its own (its feature plugins stay loaded) logged `InterfaceUnavailable: expired attachment` for every Karma, Special, UI, World, Items, Bodies, Shop, Reports and Communication cleanup call from Core's `OnPluginEnd`, so those features kept their round state, icons, bodies and effects. `unload_plugin` marks the plugin Unloading before running its unload hooks, and the attachment liveness check in `core/src/v8host/interop_lifetime.rs` demanded an Active consumer, so every `watchOptional` service expired before the consumer could use it. Hard `use()` imports never had this check. Method calls now accept a consumer that is Active or Unloading in the same generation; the context is dropped synchronously after the hooks, and attachment registration (`on`, `scope.own`) still needs Active. The provider must still be Active. Live check: `sm plugins reload ttt-core` mid-round logs none of the `provider unavailable` warnings, and the old round's icons, bodies and HUD are gone before the new Core starts.

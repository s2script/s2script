**HudInput unhook and small speed cleanups (2026-11-18). Unit-tested, not live-tested.** Five small per-frame or per-command costs found by the runtime-speed research. `HudInput` (games/cs2/js/hudinput.js) subscribed `UserCmd.onRun` on the first Tab arm and never let go, so every plugin that had ever armed Tab ran JS for every command of every player; it now holds the subscription only while a slot is armed (dropped with `__s2_scope_dispose` on the last disarm or disconnect, and every slot starts from "Tab released" when it subscribes again, as on the first arm). `replay_entity_event` (core/src/entity.rs) built three strings before finding no subscriber (199 ns per entity event); it now returns first. The ui.js pre-frame focus reconciler no longer copies an empty list every frame. `hide_hud::sweep` walked every plugin's mask map for all 64 slots each frame; with nothing hidden it now does two checks. The JS multiplexer (core/src/jsmux.rs) built the channel name's V8 string, breadcrumb tag and crossing-stack copy on every crossing; they are now built once per channel (bounded at 512 per kind, since client command names come from clients) and kept with the multiplexer's context. Live check: `sm frames` after a few minutes on a populated server shows no change in behaviour and a lower s2script share; a Tab-armed HUD still activates on the first press.

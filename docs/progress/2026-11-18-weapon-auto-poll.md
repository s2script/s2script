**Weapon card polling (2026-11-18). Unit-tested, not live-tested.** `GameHud.weapon.auto` read every player's pawn on every game frame and rebuilt the slot list each time; in Node fakes at 32 players that was 77 us and about 15 KB of garbage a frame. `games/cs2/js/gamekit-weapon.js` now reads each player once every 4 frames (about 16 Hz at 64 tick; slower would skip numbers on a rifle's count), with the turn set by the slot so a full server reads a quarter of its players per frame; a player not read yet is read at once. The held weapons and the slot list are read every 4th read and on every switch, and the same slot list object is painted between rebuilds. Same fakes after: 12.5 us and about 4.5 KB a frame. API unchanged. Live check: the card follows shots, reloads and switches with no visible lag, and `sm frames` with 30+ players shows a smaller OnGameFrame post share.
